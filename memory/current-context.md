- **知识做成工具无关 markdown + 通用 `AGENTS.md`**，不绑定单一客户端（团队工具混用：Claude/Codex/workBuddy/zcode）
- **公司代码不上第三方平台**：`bwt-vms-agent/` 上 GitHub 私有仓库；产品代码压成内部包走内部渠道分发。
  智能体需要读代码时**先向交付人员要代码包**，不许凭文档推断。详见 `打包与上传清单.md`
- **内网 IP 保留但标注清楚**：文档里的 `192.168.x.x` 只说明"环境长什么样"，**不代表可以随便连**；
  连接 / 改 / 删都要先说明→备份→再确认（见 `AGENTS.md` 红线第一节）
- **凭据不进仓库**：已全部替换为占位符，脚本改读环境变量；真值向交付负责人索取（`knowledge/凭据获取说明.md`）
- **台账按船隔离**（`ships/<船号>.md`），不按人
- **环境连接信息不写死**：每人环境不同，每次会话现问再连
- **现场库 = 生产，默认只读**，写需确认；mimic 表只允许整库数据目录备份
- **知识三层权威**：`已确认` > `实战验证` > `AI 生成待验证`；冲突时"看谁真正执行"（如 datacap 的 C++ 枚举 > DB 字典表）
- **菜单归类是业务判定**，不能靠算法（关键词命中率仅 65%），必须用交付给的规划

## 已知坑（详见记忆与技能，这里只列最易踩的）

| 坑 | 要点 |
|---|---|
| `DataTypeRegister` 的 2/8 | iscu 库 `registerdatatype` 字典表**标反了**；以 datacap C++ 枚举为准（2=无符号、8=有符号） |
| FC04 地址基址 | **30001**（FC03 才是 40001）；第三方清单常需 `30000+清单地址` |
| `SatelliteSpeedLog` 缺通道 | 与 SpeedLog 二选一（优先 SpeedLog），两个定义都保留、只接一个。**不是漏接，别补齐** |
| `way_type` XML 与库不一致 | 实船 XML=3、iscu 库=13，原因不明 —— **各保持原值，别"统一"** |
| 计程仪端口 | 是 **4008** 不是 4007（现场接线如此） |
| 流量计岸端 key | ≠ 船端别名（两台表船端别名相同，岸端另编） |
| 落库 SQL 丢 SET 语句 | 按 `;` 切分后**逐条剥注释行**，别按 `--` 整块过滤（会把 `SET @ship=…` 丢掉，全插成 `ship_id=NULL`） |
| 口述/凭记忆的资料 | 实测多次有误（串口规划、AMS 采哪几张表）——**有实文件就以文件为准** |
