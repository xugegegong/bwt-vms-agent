# SVG生成强制规则手册（Skill 入口）

## 使用场景

当用户需要生成或修改船舶智能化系统的SVG监控图时，本 Skill 自动触发。典型场景包括：

1. **生成新设备SVG图** — 用户提供参考图/草图，要求生成SVG代码
2. **修改现有SVG** — 用户上传SVG代码，要求修正布局/绑定问题
3. **平台绑定排障** — 用户反馈绑定后只变色不显示数值，或点击无反应
4. **规范化审查** — 用户要求按手册规则检查现有SVG代码
5. **清理设计工具导出** — 用户上传 Sketch/Figma 导出的 SVG，要求清理为可绑定格式

## 触发关键词

- SVG, svg, 工况点, 绑定, 监控图, 液位, 液货, 配电板, 柴油机, 模拟量
- 实时数据, float, 报警, 圆点, 状态灯, 指针, 仪表盘
- 船舶, 船用, 采集系统, 通导设备, GPS, AIS
- Sketch, Figma, 导出, 清理, 规范化

## 工作流

1. **读取手册**：先读取 `references/SVG生成强制规则手册_实战排坑版.md`
2. **分析需求**：判断是生成新图、修改旧图、排障、还是清理设计工具导出代码
3. **执行规则**：严格按手册十一章规则 + 第十一章排坑指南执行
4. **生成/修正代码**：输出符合规范的SVG代码
5. **校验清单**：逐项检查手册第十章校验清单 + 第十一章绑定前必查项

## 核心规则速查（必须背熟）

| 规则 | 要求 | 常见错误 |
|------|------|----------|
| 命名空间 | `xmlns` + `xmlns:xlink` 必须同时存在 | 漏掉 `xmlns:xlink` |
| viewBox | 必须与 width/height 严格一致 | 使用偏移或缩放 |
| 背景适配 | 背景 `<rect>` 不得超过 viewBox 范围 | 背景 rect 比 viewBox 宽/高 |
| 结构层级 | `<svg> → <defs> → <g id="页面-1"> → <g id="业务模块">` | `<defs>` 位置错误 |
| 语义分组 | 逻辑区块使用语义 `id`，如 `id="oil01"`、`id="报警列表区"` | 全部使用无意义的 `组-1329` |
| 无 class | 严禁 `class` 属性 | 使用 `class="xxx"` |
| 无 style | 严禁 `<style>` 标签和内联 `style=""` | 使用内联样式 |
| 文本结构 | 所有 `<text>` 必须包含 `<tspan>` | 直接写文本内容 |
| 无 use 复用 | 工况点元素必须直接内联，禁用 `<use>` | 用 `<use>` 引用圆点/方框 |
| **pointer-events** | **"???" 文本严禁添加 `pointer-events="none"`** | 按手册6.2添加导致绑定失败 |
| 元素顺序 | **标签 → rect → "???" → 单位** | 顺序颠倒导致平台遍历失败 |
| DOM 相邻 | **rect 与 "???" 必须紧凑无换行** | 中间有空白文本节点 |
| 数值无 id | "???" 文本不设 `id` | 设 id 与平台绑定冲突 |
| 画布紧凑 | viewBox 根据内容裁剪，无大量空白 | 右侧/底部留大量空白 |
| 无注释 | 生产 SVG 严禁 `<!-- -->` 注释 | 遗留 Sketch Generator 注释 |
| 无单字母ID | 禁止 `id="a"`~`id="z"` 等无意义命名 | 主机.svg 式单字母ID |
| 无导出垃圾 | 清理 `fill-rule="evenodd"`、camelCase 属性 | Sketch/Figma 导出残留 |
| 无图片包装 | 禁止 Base64 图片冒充 SVG | `ship.svg` 式图片包装器 |
| 字号规范 | 允许 9,10,13,15,16,18,20 等 | 使用任意小数字号 |
| 圆角允许 | 数据框可用 `rx="2"`，工业矩形禁用 | 母线/舱壁加圆角 |
| 字重允许 | 标题/按钮可用 `font-weight="bold"` | 全篇统一默认字重 |
| 文本对齐 | 允许 `text-anchor="middle"` 居中 | 手动计算 x 坐标居中 |

## 排坑速查（绑定失败时优先检查）

| 现象 | 根因 | 修复方案 |
|------|------|----------|
| 绑定后 rect 变红/绿，但 "???" 不显示数值 | `pointer-events="none"` 阻断平台遍历 | 移除所有 "???" 上的 `pointer-events="none"` |
| 绑定后 rect 不变色，数值也不显示 | 元素用了 `<use>` 复用，平台无法访问 | 改为直接内联定义 |
| 绑定后颜色正常，但数值显示错位 | 元素顺序错误（rect 在标签之前） | 恢复为：标签 → rect → ??? → 单位 |
| 部分模块正常，部分模块数值不更新 | rect 与 ??? 之间有换行/空白节点 | 紧凑排列：`<rect/><text>???</text>` |
| 点击绑定无反应 | 文本覆盖在图形上且无 `pointer-events="none"` | 给覆盖文本加 `pointer-events="none"`，但**"???" 本身不加** |
| 全部模块都不绑定 | SVG 内有 `<!-- -->` 注释干扰 DOM 遍历 | 删除所有注释节点 |
| 平台报 "找不到元素" | 使用了单字母 `id` 与平台预期不符 | 改为有意义的 `path-N` 或语义ID |
| 文字显示异常/错位 | Sketch 导出的 camelCase 属性未清理 | `fontFamily` → `font-family` 等 |
| 文件巨大但内容极少 | Base64 图片包装在 `<image>` 中 | 改用纯 SVG 绘制或直接使用图片格式 |

## 使用示例

### 示例1：生成新图
```
用户：给我生成一张船舶液货泵压力监控图，参考这个草图 [图片]

AI：
1. 读取本 Skill 手册
2. 分析草图结构（模块数量、行数、元素类型）
3. 按手册规则生成 SVG 代码
4. 输出代码 + 校验清单
```

### 示例2：修正绑定问题
```
用户：绑定后框框变红但不显示数值

AI：
1. 读取用户上传的 SVG
2. 检查：是否有 pointer-events="none"？ → 有，移除
3. 检查：元素顺序是否正确？ → rect 在 PRESS 之后，恢复顺序
4. 检查：rect 与 ??? 是否紧凑？ → 有换行，紧凑化
5. 输出修正后的代码
```

### 示例3：规范化审查
```
用户：帮我检查这个 SVG 是否符合规范

AI：
1. 读取 SVG 代码
2. 逐项检查手册第十章校验清单 + 第十一章绑定前必查项
3. 输出问题列表和修正建议
```

### 示例4：清理 Sketch/Figma 导出代码
```
用户：这是设计师给的 SVG，帮我改成能绑定的

AI：
1. 读取 SVG，识别为 Sketch 导出风格
2. 清理：删除 <!-- Generator: Sketch ... --> 注释
3. 清理：将 fontFamily/fontSize 改为 font-family/font-size
4. 清理：删除无意义的 fill-rule="evenodd"、stroke="none"
5. 清理：将深层嵌套的 translate 简化为合理层级
6. 重构：将 <use> 引用的工况点元素改为直接内联
7. 输出清理后的代码 + 变更说明
```
