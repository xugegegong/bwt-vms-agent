## 一、三个文件的分工

```
设备(RS485/NMEA) → MOXA 串口服务器 → datacap → TCP:5165 → transplatform → Kafka → 岸端
                                      ↑                      ↑
                          LocalGateway.xml              transplatform/config.xml
                          system_config.xml
```

| 文件 | 属于 | 管什么 |
|---|---|---|
| **LocalGateway.xml** | datacap | **每个通道的 IP/端口/模式**（iscu 库里不存 IP！） |
| **system_config.xml** | datacap | iscu 库连接、本船 MMSI/IMO、PNG 参数、Modbus 参数、上报目标、Kafka |
| **transplatform/config.xml** | transplatform | 监听端口、**MMSI ↔ ship_id 映射**、Kafka 主题模板 |

### ★ deviceinfo 里的通道 ≠ LocalGateway.xml 里的通道（重要，别误判为漏接）

**实船：`deviceinfo` 有 8 个通导通道（含 `SatelliteSpeedLog`），但 `LocalGateway.xml` 只接了 7 个（缺 channel_code=5）。这是正常的、刻意的。**

原因（2026-09-28 确认）：**船上可能同时存在 `SatelliteSpeedLog`（卫星计程仪）和 `SpeedLog`（速度计程仪），但本系统同时只支持一个**。规则：

> **同时存在时优先用 `SpeedLog`；没有 `SpeedLog` 时才用 `SatelliteSpeedLog`。**
> 因此两个通道定义都要**保留**（作后备），只在 `LocalGateway.xml` 里接实际使用的那个。

本船用了 SpeedLog（code 6 / 端口 4008），SatelliteSpeedLog（code 5）**没接、数据为空，属预期行为**。
→ `channel_num=7` 记的是 **XML 里实际接了几条**，不是 deviceinfo 行数。**不要拿 deviceinfo 行数去改 channel_num，也不要"补齐"缺失的通道号。**

### net_mode（实锤）
| 值 | 含义 | 实船用法 |
|---|---|---|
| **2** | 监听（被动收推送） | 通导：`ip=0.0.0.0` + 端口，`reply=0` |
| **4** | 作 TCP client 主动连 | 机舱：`ip=192.168.2.233` + 端口，`reply=1` |

> ⚠️ 通导是 **net_mode=2 被动监听**，所以 **通导 MOXA 的 IP 不在这份文件里**——它配在 MOXA 自己身上（要求它把数据推到 `192.168.2.102:400x`）。

## 七、★ 岸端 device_key 与船端别名的关系（S2 前置知识）

| 数据类别 | 船端 `iscu.hldkeymap.KeyValue` | 岸端 `vms_sys_db.tab_engine_param.device_key` | 是否一致 |
|---|---|---|---|
| AMS 模拟量 | `4000100` | `4000100` | ✅ 一致 |
| AMS 开关量位 | `4110101` | `4110101` | ✅ 一致 |
| 阀控 | `4150100` | `4150100` | ✅ 一致 |
| 通导 | `1101001` | `1101001` | ✅ 一致 |
| **流量计** | `3016800`（两台**相同**） | `30016800`（NO.1）/ `30016900`（NO.2） | ❌ **不一致** |

- 7 位 key 共 **940** 个 = AMS1 777 + 阀控 122 + 通导 41，**船端别名 = 岸端 device_key**
- 8 位 key 共 **14** 个 = 流量计 7×2。两台流量计的船端别名相同（同寄存器不同 SlaveId），**岸端必须另编一套来区分**，命名 `NO.1流量计xxx` / `NO.2流量计xxx`
- ⚠️ 流量计的岸端 key 与船端别名**不是同一个值**，配 S2 时不能照抄

## 八、已确认 / 注意事项

1. **`way_type` XML 与库不一致 —— 就让它不一致**：XML 里 EngineData `way_type=3`，`iscu.ways.WayType=13`。原因不明（2026-09-28 确认），**两边各保持原值，不要"统一"**。
2. **通导计程仪端口 = 4008**（2026-09-28 确认：现场接线就是这样，**4007 确实没人用**）。按实船配，别"纠正"成 4007。
3. **`SatelliteSpeedLog` 保留不删**：见第二节——它是 SpeedLog 的后备，两个通道定义都要留着，只在 XML 里接实际用到的那个。
4. **通导 MOXA 的 IP** 不在这两个文件里（net_mode=2 是被动监听，datacap 只管监听端口），只能看 MOXA 自身配置。
5. **`system_config.xml` 的 `modbus_params`** 是实船有、源码模板没有的新增段——说明**现场 datacap 版本比工作区源码新**，以实船为准。
6. **用户口述的"串口服务器规划"可能有误**（凭记忆写的）：已发现阀控位置错位、计程仪端口错 1。**一切以 `LocalGateway.xml` 实文件为准。**
