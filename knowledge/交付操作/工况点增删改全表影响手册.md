## 0. 十张表全景(含导出清单里的四张遗留表)

```
【活表——工况点增删改必须关注的】
tab_engine_param              工况点主表(一切前提)
tab_engine_param_relationship 点↔菜单绑定(不挂=前端看不到)
tab_engine_param_menu         菜单树(整树删重建模式)
tab_engine_state_quantity_cfg 状态量(device_type=2)值→文本/颜色映射
tab_statistics_param          信号路由(能效/统计用,改key时被联动)
tab_ship_info / tab_ship_info_extend  船档案+额定参数KV(27/28/70/107被能效引用)

【遗留表——不需要动,原因如下】
tab_md_orderkey     废弃的PNG解码映射(order_id已并入tab_engine_param,勿再写)
tab_navigation_param 老通导配置,仅 realTimeData 启动加载做'--'补位;新体系=tab_engine_param(order_id≤100)+tab_sys_dict
tab_alg_para        老算法脚本引擎参数表,全库零代码引用(死表)
tab_alg_script      老算法脚本目录表,零代码引用(死表)
```

**三种类型速查**(device_type):**1=数值量(数字量)**、**0=报警量**、**2=状态量(开关量)**。
清洗侧 dataCleanV2 把 **0 和 2 同按开关量处理**;trans_data 公式对任何类型都可存。

## 1. 新增一个工况点

接口 `POST /config/visual/engine/backend/save`(可视化"工况点配置"保存按钮;前端 id=null 即新增)。**该接口无事务**(注解被注释)。

### 表操作(数值量/报警量/状态量共同部分)

| 序 | 表 | 操作 | 说明 |
|---|---|---|---|
| 1 | tab_engine_param | INSERT | 动态列:非空才插。**device_id 由后端生成**(`UUID.randomUUID().replace("-","")` 32位无横线);node_type 恒 '2'(叶子);status 默认 '1';id/create_time/update_time 走 DB 默认。**father_id/device_father_id/unify_device_key/original_key 全部不填(NULL)**——现行"挂菜单"只靠 relationship,这四列是历史遗留 |
| 2 | tab_engine_param_relationship | 先 DELETE(防御性,新UUID删不到) 后 INSERT | **只有前端传了 menuDeviceId 才插**;不传=孤儿点(库里存在、任何菜单看不到) |

### 分类型差异

| 类型 | 额外操作 | 不做的后果 |
|---|---|---|
| 数值量(1) | 补 min/max(量程)、unit;需要公式时另走 `/backend/more/save` 存 trans_data | 前端无刻度/单位 |
| 报警量(0) | 补 low/low_low/high/high_high(阈值就是主表列,**没有独立报警配置表**) | 报警不判 |
| 状态量(2) | **另走 `/backend/more/save`** 存 tab_engine_state_quantity_cfg(state_data JSON) | 前端显示空/无色 |

⚠️ **新增单点不碰** tab_statistics_param(只有能效"信号路由"保存才建)——但若该点要参与能效计算,新增后须去信号路由配置,或手插 statistics_param。

### 新增的 SQL 手工版(照抄改参数)

```sql
-- ① 主表(数值量示例;报警量把量程换 low/high;状态量全部 NULL)
INSERT INTO tab_engine_param
  (ship_id, device_name, device_name_en, node_type, device_type, device_key, order_id,
   device_id, min_value, max_value, unit, status)
VALUES
  (35701001, '9103 轴功率/指示', '9103 Shaft Power/Ind.', '2', '1', '41021', 611,
   REPLACE(UUID(),'-',''), 0, 5000, 'KW', '1');

-- ② 挂菜单(必做!)
INSERT INTO tab_engine_param_relationship (ship_id, menu_device_id, engine_device_id, status)
VALUES (35701001,
  (SELECT device_id FROM tab_engine_param_menu WHERE ship_id=35701001 AND device_name='主机' AND menu_type='1' LIMIT 1),
  (SELECT device_id FROM tab_engine_param WHERE ship_id=35701001 AND device_key='41021'), '1');

-- ③ 仅状态量(2):状态映射
INSERT INTO tab_engine_state_quantity_cfg (ship_id, device_key, state_data)
VALUES (35701001, '45084',
 '{"0":{"statusCn":"RUN","statusEn":"RUN","color":"#41D321"},"1":{"statusCn":"STOP","statusEn":"STOP","color":"#8E8E8E"}}');
-- 0/1 语义先看 AMS 清单"数据"列(如 0=NORMAL/RUN 1=ALARM/STOP),填反=RUN/STOP 颠倒
```

## 2. 修改一个工况点

同一接口(`/backend/save`,id≠null)。**代码级陷阱最多,逐条看**:

### 主表 UPDATE 规则(必知)

| 规则 | 代码行为 | 交付含义 |
|---|---|---|
| **order_id / device_id 不可改** | 后端强制回填旧值,UPDATE SQL 里没有 order_id 列 | 要换 order_id 只能删了重加 |
| **7 个量程列无条件覆盖** | `min_value,max_value,low_value,low_low_value,high_value,high_high_value,unit` 不在动态 if 里 | **前端漏传哪列哪列被写成 NULL**——可视化改一个量程,其他量程若页面没带全就丢!手工 SQL 用单列 UPDATE 最稳 |
| 名称/类型/device_key | 非空才更新 | 改名称不会误伤其他列 |

### 每次保存必发生的联动(updateDeviceRelation,即使 key 没变)

| 序 | 表 | 操作 | 注意 |
|---|---|---|---|
| 1 | tab_statistics_param | **删旧 key 全部行 → 改新 key → 逐行重插** | id 重新自增、create_time 重置;若该点没配信号路由则无感 |
| 2 | tab_engine_state_quantity_cfg | 同样删旧重插 | 功能无损但行 id/时间变;**此逻辑不判 device_type** |
| 3 | tab_engine_param_relationship | 删该点全部绑定 → 按本次 menuDeviceId 重插 | 传空 menuDeviceId = 点脱离菜单! |

**无事务**:任一步抛错即停在中途,典型脏状态——statistics_param/state_cfg **已删未插**(配置永久丢)、relationship 已删未插(点从菜单消失)。批量 save2 某条失败,前面已生效。

### 分类型修改要点

| 类型 | 改什么 | 怎么做 | 坑 |
|---|---|---|---|
| 数值量 | 量程/单位 | 单列 UPDATE 或可视化(注意 7 列覆盖陷阱) | |
| 数值量 | 公式 | `/backend/more/save` 传 transData(格式 `{通道号}*0.1`,清洗期用 exp4j 求值**覆盖原值**) | 公式错误=实时值全错 |
| 报警量 | 阈值 | 主表 low/low_low/high/high_high 列 | 同 7 列覆盖陷阱 |
| 状态量 | 状态映射 | `/backend/more/save` 传 stateData JSON | ⚠️ **对已改成非 2 类型的点调 more/save,会把已有 state_data 删掉且不回插(静默丢失)**;类型 0/1 的点别再调 |
| 任意 | 改 device_key | 可视化会联动 statistics/state_cfg/relationship + 船端同步 datacap(岸端环境不做船端联动,需手工核 iscu) | key 变了 hldkeymap 没变 → 解码错位 |
| 任意 | 改类型(0↔1↔2) | 改 device_type 列;**改完检查 state_cfg**:变 2 要补状态映射,变 0/1 要删残留映射 | 残留映射可能导致颜色异常 |

### 修改的 SQL 手工版(最稳,单列定向)

```sql
-- 只改名称(两套都要)
UPDATE tab_engine_param SET device_name='新名', device_name_en='New Name'
WHERE ship_id=? AND device_key='xxx';
-- 只改量程(单列,不碰其他)
UPDATE tab_engine_param SET min_value=0, max_value=5000, unit='KW'
WHERE ship_id=? AND device_key='xxx';
-- 换菜单
UPDATE tab_engine_param_relationship r
JOIN tab_engine_param p ON p.device_id=r.engine_device_id AND p.ship_id=r.ship_id
SET r.menu_device_id=(SELECT device_id FROM tab_engine_param_menu WHERE ship_id=? AND device_name='新菜单' AND menu_type='1' LIMIT 1)
WHERE p.device_key='xxx';
-- 改类型 2→0 后清残留状态映射
DELETE FROM tab_engine_state_quantity_cfg WHERE ship_id=? AND device_key='xxx';
```

## 3. 删除一个工况点

接口 `/backend/delete`(传 id)。**有事务**,级联顺序(代码执行序):

| 序 | 表 | 条件 | 说明 |
|---|---|---|---|
| 1 | tab_engine_param_relationship | ship_id + engine_device_id | **硬删,无 status 过滤** |
| 2 | tab_statistics_param | ship_id + device_key | |
| 3 | tab_engine_state_quantity_cfg | ship_id + device_key | |
| 4 | tab_engine_param | id(物理删,非软删) | |

**不级联的遗留**(删后手工核对):
- mimic 图绑定(sys_engine_mimic_analog/status)→ 图上该点显示空
- 船端 iscu(hldkeymap/JsonString)→ 采集通道仍在采数(占带宽不入库展示)
- 菜单表本身不动

### 删除的 SQL 手工版(三种类型同套)

```sql
SET @dk='xxx', @sid=35701001;
DELETE FROM tab_engine_param_relationship WHERE ship_id=@sid
  AND engine_device_id=(SELECT device_id FROM tab_engine_param WHERE ship_id=@sid AND device_key=@dk);
DELETE FROM tab_statistics_param WHERE ship_id=@sid AND device_key=@dk;
DELETE FROM tab_engine_state_quantity_cfg WHERE ship_id=@sid AND device_key=@dk;
DELETE FROM tab_engine_param WHERE ship_id=@sid AND device_key=@dk;
-- 可选:mimic 绑定残留清理(按绑定表结构)
```

## 4. 可视化页面操作 → 数据库影响对照表

| 页面操作 | 接口 | 数据库变化 | 风险 |
|---|---|---|---|
| 工况点配置-新增/保存 | /backend/save | INSERT param(+relationship) | 无事务;孤儿点(menuDeviceId 空) |
| 工况点配置-修改保存 | /backend/save | UPDATE param + **删插 statistics_param + state_cfg + relationship** | **7 列覆盖**;中断即脏;**改个名字也会重建三表行** |
| 工况点配置-删除 | /backend/delete | 四表级联删(有事务) | mimic/采集不级联 |
| 更多配置(公式/状态量) | /backend/more/save | UPDATE trans_data + 删插 state_cfg(仅 type=2 回插) | 非 2 类型调用 → 状态映射静默丢 |
| 菜单保存 | /engine/menu/save | **整树删 tab_engine_param_menu 重建** + relationship 中不在新树的绑定全删 | 前端漏传 deviceId → 绑定全清;健康菜单还会同步 mmha_component |
| Excel 导入(船端) | /upload | 先**全船清空 state_cfg** + 删 order_id 空的 param,再逐行"冲突即删旧插新" | 状态量配置易丢 |
| 能效-信号路由保存 | /energyefficiency/device | 按设备删插 statistics_param | 见风险清单文档 |
| 通导保存 | /navigation/save | 删 order_id≤100 的 param 整批重插(船端还同步 iscu) | 老点 custom 配置丢失 |
| 机舱 Excel 导出/配置导出 | /export/file/* | 只读+写导出记录表 | |

**改完任何配置**:清 Redis 菜单缓存由后端自动做(`engine:menu:{shipId}:{menuType}`);前端需 Ctrl+F5。

## 5. 遗留表总览(为什么不用动,详见 5a-5d)

四张遗留表:**tab_md_orderkey**(废弃勿写)/ **tab_navigation_param**(仅'--'补位)/ **tab_alg_para + tab_alg_script**(零引用死表)。另有关联表 tab_ship_info_extend 详见 5d。

## 5a. 遗留表:tab_md_orderkey(废弃,勿再写)

原为
PNG 解码映射老表(order_id↔key_name)。2024-01 迁移已把 order_id 回填进 tab_engine_param(UPDATE join 一次性完成),业务代码零引用(health 里只剩被注释的死代码)。**它还在导出清单里纯属历史**(tab_export_config id=4 机械搬运)。
- 新增点:**不写**。硬约束 = tab_engine_param.order_id ↔ iscu.hldkeymap.orderkey 一一对应且 >100(机舱点)
- 建议:`UPDATE tab_export_config SET status=0 WHERE id=4;` 停用导出项(停用后导入文件里如有该 sheet 会报错,需同步删 sheet)

## 5b. 遗留表:tab_navigation_param(老通导,仅'--'补位)
每船固定几十行(sog/cog/风/舵角…name_eng→ais_key/gps_key)。**唯一活代码**:realTimeData 启动加载,用于"AIS 报文缺值时给航行监控页补 '--'"。解码/计算/新通导配置(2024 起)都走 tab_engine_param(order_id≤100)+tab_sys_dict(navigation_param 字典)+ /navigation/save。
- 新增通导点:**不需要动它**;不动仅影响新点的"--"补位显示,零业务影响
- 老船懒得清可留着(只读不写)

## 5c. 遗留表:tab_alg_para / tab_alg_script(零引用死表)
2019 年代"可配置算法脚本引擎"遗迹(script 目录+参数 KV)。全库 15 个模块**零代码引用**,标准库为空表,与 device_key 无关。新增点不需要写,写了也没人读。可从导出清单/现场库清除。

## 5d. 关联表:tab_ship_info / extend(额定参数27/28/70/107,能效静默依赖)
- 建船时依次:写 ship_info → extend → 生成 39 默认通导点(tab_engine_param)→ 报警映射 → EEXI 默认行 → 建 vms_{shipId}_base_db 库
- **extend 额定参数被能效静默引用**(缺了不报错、直接跳过不出数):paramId **27=主机额定功率、28=主机额定转速、70=发电机额定功率、107=轴发额定功率**(另有 102 发电机负载阈值/103 锅炉关停阈值/104 SFOC P_opt)。realTimeData 每 5 分钟全表重载;负载率=Σ实际/(台数×额定),无主机功率点时用 `额定功率/额定转速³×转速³` 估算——**27/28 缺失则能效负载率/CII 直接不出数且日志只有 debug 级**
- 值列名是 **param_value**(不是 value)

## 6. 坑大全(按出现频率)

| # | 坑 | 场景 | 规避 |
|---|---|---|---|
| 1 | 忘挂 relationship | 新增点前端看不到 | SQL 必插②;可视化必选菜单 |
| 2 | 状态量忘配 state_cfg | type=2 显示空/无色 | 新增后跑 more/save 或手插③ |
| 3 | 修改用可视化整页保存 | 其他量程列被 NULL 覆盖 | 改单列用手工单列 UPDATE |
| 4 | 类型改 0/1 后调 more/save | 状态映射被静默删 | 改类型后手动清/补 state_cfg |
| 5 | order_id 想改 | 后端锁死 | 删了重加;或手工 SQL(慎重,必须同步 iscu) |
| 6 | 手删只删主表 | statistics/state_cfg/relationship 残留孤儿行 | 按第 3 节四表顺序删 |
| 7 | 删点后图上显示空 | mimic 绑定残留 | 同步清理绑定表 |
| 8 | 能效页负载率不出数 | extend 缺 27/28/70/107 | 补 INSERT,值列 param_value |
| 9 | 英文名没填 | 英文页面空白 | 两套名称永远一起填 |
| 10 | 菜单整页保存 | 绑定全清(前端漏传 deviceId) | 高危操作前备份;见《配置中心数据安全风险清单》 |
| 11 | 0/1 语义填反 | RUN/STOP 颠倒 | 按 AMS"数据"列核对 |
| 12 | 给非状态量点配 state_data | 无效+可能误导排错 | state_cfg 只对 type=2 生效 |
