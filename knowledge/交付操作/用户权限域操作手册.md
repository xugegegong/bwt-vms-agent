# 用户权限域操作手册(建账号/授权)

> 更新日期:2026-09-04(修改本文档后请同步更新此日期,并到 Dify 知识库重新上传该文件)
> 场景:给客户开账号/建职能授权/岸基船端用户/spadmin 密码/登录不了排查。

---

## 1. 账号体系 30 秒

```
spadmin(Nacos配置,不进数据库,level 0)──── 管理员级,不能建用户!
admin(种子库自带,admin/<密码>,level 1)── 可以建各级用户
tab_user_info(账号) + tab_login_user_info(登录别名,登录入口!) + tab_user_role(船+职能)
tab_role_info(职能) + tab_role_resource(职能↔资源) + tab_resource(150行资源树,装机自带)
等级:0=spadmin 1=admin 2=系统用户(全部船) 3=岸基用户(按船配) 4=船端用户(船由航次定)
```

**三个关键事实**:
1. **登录靠 tab_login_user_info**(登录名/手机/邮箱各一行别名 JOIN user_info)——只插 user_info 不插别名 = 永远登录不了(最常见的坑)
2. **spadmin 账号密码在 Nacos**(`user-account.loginName/userName/password`,@RefreshScope 可热改),不走数据库
3. **密码算法**:`MD5(Base64(UTF8(明文)))`,SQL 里用 `MD5(TO_BASE64('明文'))`

## 2. 新建客户账号(交付最常用)

### 路线 A:可视化(有 admin 账号时,推荐)
1. spadmin 登录 → 系统设置 → **职能管理** → 添加职能(用户类型选"岸基用户")→ 权限树勾菜单/按钮 → 保存(自动写 role_info + role_resource)
2. **用户管理** → 添加用户:用户类型=岸基用户、登录名/姓名/手机、初始密码、勾船+职能(必须至少 1 船 1 职能 + 选默认船)
3. 注:spadmin 不能建用户(代码限制),由 admin 建


## 2b. 新建客户账号:路线B SQL 冷启动(空库/只有 spadmin 时)
```sql
-- ① 建 admin(若没有;种子库自带 id=1 的 admin/<密码>)
INSERT INTO tab_user_info (create_user_id, company_id, login_name, passwd, user_name,
  privilege_level, language, skin, status, user_license)
VALUES (999999999, NULL, 'admin2', MD5(TO_BASE64('Admin@123')), '管理员', '1', 'zh', 'deep', '1', '1');
SET @uid = LAST_INSERT_ID();
INSERT INTO tab_login_user_info (user_id, login_name, status) VALUES (@uid, 'admin2', '1');


## 2c. 建职能与授权(SQL,路线B续)

```sql
-- ② 建职能(岸基)
INSERT INTO tab_role_info (create_user_id, role_name, role_name_en, status, user_type)
VALUES (@uid, '客户查看', 'Customer Viewer', '1', '3');
SET @rid = LAST_INSERT_ID();
-- 授权:按 identification 挑资源(可先全给再删)
INSERT INTO tab_role_resource (role_id, resource_id, status)
SELECT @rid, id, '1' FROM tab_resource WHERE status='1' AND is_show='1'
  AND identification IN ('NavigationMonitoring','ChartRoute' /* 按交付范围选 */);
```

## 2d. 客户账号与绑船(SQL,路线B续)

```sql
-- ③ 客户账号(level 3)
INSERT INTO tab_user_info (create_user_id, company_id, login_name, passwd, user_name,
  privilege_level, language, skin, status)
VALUES (@uid, NULL, 'customer01', MD5(TO_BASE64('Init@12345')), '张三', '3', 'zh', 'deep', '1');
SET @cid = LAST_INSERT_ID();
INSERT INTO tab_login_user_info (user_id, login_name, status) VALUES (@cid, 'customer01', '1');
-- 绑船+职能(def='1' 默认船;level 2 要给每条船都插一行)
INSERT INTO tab_user_role (user_id, ship_id, role_id, status, def)
VALUES (@cid, <ship_id>, @rid, '1', '1');
```

## 3. 登录排错速查

| 症状 | 根因 | 处理 |
|---|---|---|
| 只有 spadmin 能登,其他全"用户名或密码错误" | tab_user_info 空(用户表被清过) | 路线 B 重建 |
| 账号存在仍登不了 | tab_login_user_info 没插别名行 | 补 INSERT |
| "账号船舶无效/权限不足" | level 3 没有 def='1' 的有效船/职能行 | 补 tab_user_role,船和职能 status 都要 '1' |
| 登录名用 spadmin 建客户号 | 保留字,校验拒绝 | 换名 |
| 改了权限不生效 | token 里缓存 UserInfo | 重新登录 |
| spadmin 密码忘了 | 在 Nacos `bwt-vms-system.yml` 的 user-account.* | 改 Nacos 热生效 |
| 首次登录报许可协议 | user_license=0 | 登录请求 userLicense 必须传 '1' |

## 4. 其他要点

- **Token**:JWT 6 小时滑动续期,同账号单点(新登录踢旧);网关不做认证(注释掉了),鉴权在各服务 `@PreAuthorize` 注解
- **重置密码**:界面重置有 bug(默认密码配置项缺 ${} 拼错,按字面量当密码)——**务必显式传新密码**,或直接 SQL `UPDATE tab_user_info SET passwd=MD5(TO_BASE64('新密码')) WHERE login_name='xxx'`
- **船端用户(level 4)**:只能船端环境建;在哪条船由**当前航次**决定(tab_user_flight_relation JOIN 最新 flight_record)——没建航次=船端登录无船。船员默认密码=身份证后6位,首登强制改
- **tab_resource 150 行是装机种子**,交付不要动;资源 identification 是权限控制点(资源树 resource_type:0菜单/1叶子/2接口)
- **role_resource 42 行脏数据**:当前库 role_info 空但 role_resource 有 42 行(引用不存在的角色),可清理
- **免登 token**:tab_user_permanent_token 手工插 JWT 行,每分钟自动刷 Redis 保活(给第三方免登用)
- **无登录历史表**:只有 user_info.login_time(最后登录);tab_login_user_info 是别名表不是日志

## 5. 验证 SQL

```sql
SELECT u.login_name, u.user_name, u.privilege_level, u.status, r.role_name, ur.ship_id, ur.def
FROM tab_user_info u
LEFT JOIN tab_user_role ur ON ur.user_id=u.id AND ur.status='1'
LEFT JOIN tab_role_info r ON r.id=ur.role_id
WHERE u.status='1';
-- 登录别名核对(每个能登录的账号至少 1 行)
SELECT * FROM tab_login_user_info WHERE status='1';
```
