# 航行监控域操作手册(电子围栏/航次/港口/航道)

> 更新日期:2026-09-04(修改本文档后请同步更新此日期,并到 Dify 知识库重新上传该文件)
> 来源:代码精读(ElectricFenceController/EcaAlertTask/NavigationDataServiceImpl 等)+ 142 实库验证。
> 场景:新船上线航行监控域要配什么 / ECA 不提醒 / 进港不提示 / 围栏怎么加。

---

## 1. 域数据流 30 秒

```
AIS/船端GPS → dataCleanV2 每3分钟:
  航迹清洗(DBSCAN+Douglas-Peucker压缩) → tab_res_route(轨迹)
  航程计算(相邻点距离) → tab_ais_distance_record(KM段)
realTimeData 内存几何匹配(围栏) → 进/停/离事件 → Kafka → 微信"水情动态"+WS前端弹提示
dataCleanV2/dataFlow 状态机(航速阈值+围栏) → tab_ais_ship_status_record(航行/锚泊/靠泊)
  → Kafka → system 航段生成 → tab_ais_ship_segment(自动航次:起止港/里程/油耗)
system EcaAlertTask 每3分钟 → 航向射线与ECA多边形求交 → 1小时内进出预警 → Redis eca-alert
```

## 2. 电子围栏配置(交付核心操作)

**⚠️ 前端没有围栏管理界面**——后端 API 完备(`POST /electricFence/add` 等)但无 UI,交付用 **SQL 配**:

```sql
-- ① 主表(系统级,无 ship_id,所有船共用)
INSERT INTO tab_ais_electric_fence (name, type, grade, status)
VALUES ('XX港围栏', 1, 1, '1');   -- 见下方 type 表;grade 数字越小优先级越高
SET @fid = LAST_INSERT_ID();

-- ② 顶点:多边形 ≥3 点按 order_num 顺序连(自动闭合)
INSERT INTO tab_ais_electric_fence_info (electric_fence_id, lat, lon, order_num)
VALUES (@fid, 31.2304, 121.4737, 1), (@fid, 31.2350, 121.4800, 2), (@fid, 31.2280, 121.4810, 3);
-- 圆形围栏:只插 1 条且 radius 非空(带 radius 列)

-- ③ 可选:_extend(label_name/remark,小程序推送文案)
```

**生效**:SQL 配完需等定时 reload(Nacos cron `vms.electric-fence.job.reload-electric-fence-corn`)或调 `GET http://<realTimeData>:端口/electricFence/reload`(system 的 add 接口会自动 Feign 通知,纯 SQL 不会)。

**type 硬编码行为**(与 `_type` 字典是两套编码,勿混!):

| type | 行为 | 状态机 |
|---|---|---|
| 1 港口 | 进港提示 + 航段起止港来源 | 判**靠泊** |
| 2 锚地 | 提示 | 判**锚泊** |
| 3 限速/警戒区 | 提示 + 围栏内**绿色航速**检测 | 不入库 |
| 4 ECA | EcaAlertTask 预警 + 前端画区 | 不入库 |
| 30 三峡坝 | 过坝事件 | 入库 |

**ECA 围栏是装机种子自带的**(珠三角/环渤海/长三角/中国沿海/日韩北美澳,type=4 grade=6),**不用逐船配**。

## 3. 硬约束与坑

| 坑 | 后果 |
|---|---|
| radius 非空但插了多个顶点 / lat 或 lon 为 NULL | **整条围栏被静默丢弃**(只打 debug 日志,极难排查)——配完必验证 |
| type 与 fence_type 字典混淆 | 字典 7 条(桥区/闸区/渡口…)只是管理下拉显示用,与行为无关 |
| 纯 SQL 配完不 reload | 内存里没有新围栏,一直不生效 |
| ECA 告警 Redis key(`list:ship:{id}:eca-alert`)仓库内无消费方 | 告警写了没人读,靠小程序/App 端(如有);排查 ECA 不提醒先看这个 key 有没有值 |
| dataFlow 与 dataCleanV2 有两份重叠的状态机 | 实际以 dataCleanV2+realTimeData 为准,dataFlow 是否在跑需现场确认 |
| 航迹无数据 | 检查 tab_statistics_param 是否配了经纬度点(device_type=longitude/latitude)+ tab_engine_param 量程 |

## 4. 航次与航段

**两条"航次"概念别混**:
- **tab_flight_record(人工航次)**:前端航线面板录入(`POST /sys/flight/number`),字段 flight_number/起止港(文本!无外键)/estimated_load_weight/flight_type;142 库为空=没用。长航同步(`voyage-task` cron + SOAP)也可自动插。
- **tab_ais_ship_segment(自动航段,推荐)**:状态机自动生成,起止港关联 **tab_ports**(带经纬度)+ 围栏,含里程/油耗/锚泊时间;`GET /segment/current` 给前端"当前航段"。**交付优先用自动航段,人工航次可不配**。

**港口双表**:tab_port_info(33行)=报表字典(航道流量/水情站点);tab_ports(36行)=航段业务港口(带经纬度,由"标准里程"功能维护 `POST /port/addStandardMileage`,同时插 tab_segment_port_info 港对港里程)。**新航线要准点率/里程偏差 → 标准里程界面补港对**。

**验证 SQL**:
```sql
SELECT id,name,type,grade,status FROM tab_ais_electric_fence WHERE status='1';
SELECT COUNT(*) FROM tab_ais_electric_fence_info WHERE electric_fence_id=<id>;  -- 顶点数≥3或=1带radius
SELECT * FROM tab_ais_ship_status_record WHERE ship_id=? ORDER BY utc_time DESC LIMIT 5; -- 状态事件
```

## 5. 新船上线本域配置清单

系统级(不用配):ECA 围栏种子/fence_type 字典/过闸表单模板(94行)/航道坐标(2714行,一次性导入)。
逐船要配:① 船档案+MMSI ② 经纬度工况点(statistics_param + engine_param 量程)③ 绿色航速限速值(不配=围栏内不限速)④ 航次按需人工录入。
Nacos 全局参数(影响判定):启航/靠锚泊航速阈值 sog-threshold、航程聚合周期 vms.distance.cycle(默认5分钟)、节换算 knot-factor。
