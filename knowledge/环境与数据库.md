# 环境与数据库

> 本文档是"手"的说明书：当前连哪个库、怎么连、现场和测试库之间怎么来回导数据。执行任何操作前先看这里。

## ⚠️ 内网地址说明与连接纪律（先读这一节）

**本文档及套件其他位置出现的 `192.168.x.x` 等地址，均为公司内网地址，仅用于说明"该环境长什么样"。**

**它们不是"可以随便连"的意思。** 开发环境、测试环境都属于公司共享资源，纪律如下（详细红线见 `AGENTS.md`）：

1. **连之前必须先说明并取得明确指令** —— 讲清"要连哪个环境的哪个库、准备做什么"，等交付人员同意后才连。
2. **不得随意连接** 非本人负责的开发 / 测试环境；**更不得随意修改、删除**其中的数据库、配置文件、服务。
3. **即已获准连接，凡遇修改 / 删除**：先说明影响面 → **先备份** → **再问一次** → 得到明确答复才执行。
4. **换环境、换库、扩大范围** 都要重新确认，不能用一次许可覆盖全部。
5. 本文档里出现过的旧环境（如 `192.168.7.x`、`192.168.1.x`）**可能已经不用了**——连之前先跟环境负责人核对，别照着文档直接连。

## 三种工作场景

1. **交付现场**：直连**现场数据库**（实船库 = 生产）。
2. **现场未处理完**：把现场库 dump 下来 → 在酒店通过 VPN 导入**办公室测试环境**调试 → 次日把测试库导出，回导现场库。
3. **办公室**：直连**办公室测试环境**。

## 红线提醒

现场库 = 生产，默认只读；写操作必须先确认（见 AGENTS.md 红线）。

## 备份与修改策略（团队用 Navicat Premium，务必遵守）

- **备份方式 A（改部分表字段）**：Navicat 里对目标表右键备份，命名 `源表名_copy_时间戳_备注xxx`（团队习惯拼写就是 `copy`，沿用）。
- **备份方式 B（整库备份带回测试环境）**：直接备份 MySQL 数据目录，命名 `mysql_bak_时间戳_备注xxx`。
- **修改方式 C（批量改工况点单位 / 最大最小值 / device_type / trans_data 等）**：把表导出 Excel，改完再导回。

**重要坑（mimic 表）**：涉及 mimic 配置的表，用"转储 SQL"或"导出 Excel"方式备份还原后可能出问题；**只要涉及 mimic 表，建议直接备份整个 MySQL 数据目录（即方式 B）**。

## 连接信息：每次会话现问，不写死

每个人的交付环境、现场数据库都不同，套件里**不保存固定连接信息**。智能体每次开工必须先问交付人员：

1. 当前在哪个场景：交付现场 / 办公室 / 酒店 VPN 测试环境？
2. 连接信息：host / 端口 / 库名 / 账号 / 密码（或 Navicat 里对应的连接名）。
3. 这是不是生产库（现场实船库）？——决定只读还是可写。

拿到后先跑一条只读查询（`SELECT 1` 或查 ship_id）验证连通，再继续。

## 整库带走 / 回导工作流（现场 ↔ 测试，目录级）

> ⚠️ 整库备份还原**不用 mysqldump 转储 SQL**（会踩 mimic 表的坑），而是**直接备份 / 还原 MySQL 数据目录**，对应上面"备份方式 B"。

现场 → 测试（把船带回酒店调试）：

1. 停掉现场 MySQL（或用一致快照），把整个 **MySQL 数据目录**拷贝下来，命名 `mysql_bak_时间戳_备注xxx`。
2. 带回测试环境，停测试 MySQL，用备份目录整体覆盖 / 还原数据目录，再启动。

测试 → 现场（调试完回导）：

1. 反向操作：把测试环境数据目录拷回现场，**回导前先备份现场库当前数据目录**。
2. 回导后验证（尤其 mimic 相关表 / 页面）再继续。

> 说明：目录级备份还原对"库整体搬家"最稳，mimic 表不会坏。只改少量表字段用备份方式 A（Navicat 表级），批量改工况点字段用修改方式 C（Excel 导出导回）——但这两种涉及 mimic 表时同样要回到目录级备份（方式 B）。

## 已知库表速查（以代码实际为准）

- 岸端工况点库 `vms_sys_db`：tab_engine_param、relationship、state_cfg、statistics_param、tab_height_cabin、tab_equipment。
- 机舱健康 `mmha`：mmha_component、relation、model_info；Redis in/out key。
- 采集侧：ISCU 相关 8 张表 + datacap / transplatform。
- 注意：tab_height_cabin 的体积列叫 `cabin`（不是 capacity），tank_id 是 bigint。

## Redis 排查（用 RedisDesktopManager）

团队用 **RedisDesktopManager（RDM）** 可视化工具，不用命令行。排查时在 RDM 里连上对应 Redis，在 key 搜索框搜下面的 key、点开看 value（`{shipId}` 换成实际船号，如 `35701001`）。

**判断某船是否在出数（最常用）**：
搜 `list:ship:{shipId}:other` —— 这是**全部工况点实时值**。有值 = 采集链路正常；空 = 没出数，回查 datacap。

**看机舱健康分**：`list:ship:{shipId}:health`（hash，键 = 部件号，值 = `utc\t分值\t缺陷json`）；24h 趋势看 `health_cache:{shipId}:data:{桶}`。

**看能效**：`energy:{shipId}:device_power`（设备功率）、`energy:{shipId}:device_consume`（油耗）、`energy:{shipId}:cylinder_exhaust_temperature`（排温）。

**看报警**：`engine:alarm:device:{shipId}`（设备报警）、`engine:alarm:health:{shipId}`（健康报警）、`list:ship:{shipId}:healthAlarmTotal`（健康报警总数）。

**看船位 / 通导**：`list:ship:{shipId}:ais`、`list:ship:{shipId}:navigation`。

**看登录会话**：`login_token_{loginName}`（某账号的 token）。

> 完整 Redis key 字典见 `knowledge/BWT-VMS架构知识库.md` 第 14 节。
