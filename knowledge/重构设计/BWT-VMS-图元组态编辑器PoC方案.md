# BWT-VMS 机舱图元组态编辑器 · 技术 PoC 方案

> 目标:在 R2 正式排期前,用 2 周验证"图元拖拽组态(react-konva)"方案在本系统场景的可行性与性能,为决策提供依据。若通过则正式排期;若不通过则评估备选(图片热区/现成组态库)。

---

## 1. PoC 目标

验证四件事:
1. **技术可行**:react-konva 能实现"底图 + 拖拽图元 + 绑工况点 + 报警变色 + 动画 + 保存加载 + 运行时只读渲染"
2. **性能达标**:中大规模图元(200 个)下编辑/渲染流畅
3. **实施可用**:非开发人员能自助搭图(关键体验验证)
4. **资产可复用**:现有 SVG 能作图元/底图导入

## 2. 验证范围(必须做)

| 必验 | 说明 |
|---|---|
| 画布 + 底图上传 | 实施上传客户 PNG/JPG 显示为背景,可缩放 |
| 图元库拖拽 | 10-15 个起步图标,从面板拖到画布 |
| 图元操作 | 选中/移动/缩放/旋转/对齐/多选/成组/图层 |
| 数据绑定 | 图元绑 device_key,属性面板配置 |
| 报警变色 | 值区间→颜色/图标三档 |
| 动画 | 液位填充 + 阀门旋转(各 1 个) |
| 实时预览 | 填模拟工况值,图元刷新 |
| 保存/加载 | 布局 JSON 存取,无损 |
| 运行时只读 | 同画布不响应编辑,接模拟工况流刷新 |
| 中英文 | 切换 |

## 3. 不在 PoC 范围(避免发散)

- 完整图元库(只 10-15 个,覆盖主机/发电机/罐/阀/表/文本)
- 版本/回滚/diff/校验/下发/模板(复用配置中心通用能力,PoC 不验)
- 移动端适配(PoC 只验 PC + 大屏 1920)
- 旧 SVG 批量迁移脚本(只验 1 个 SVG 导入)
- 与真实采集数据联动(用模拟值发生器)

## 4. 技术选型(决策)

| | react-konva(主) | Fabric.js(备) |
|---|---|---|
| 与 React 集成 | 原生 JSX 声明式,与 React18/TS/Zustand 无缝 | 命令式,需手动桥接 |
| 学习成本 | 低(会 React 即可) | 中 |
| 生态/文档 | 好 | 好 |
| 性能 | 分层缓存好 | 好 |
| 复杂编辑器 | Transformer/对齐现成 | 现成 |

**决策**:PoC 用 **react-konva**。若性能或复杂交互不达标,备选 Fabric.js(PoC 第二周可平行验 1 天)。

**图元图标包**:PoC 用 iconfont 的"工业/电力"免费图标集(SVG/PNG,风格统一),凑 15 个起步。

## 5. PoC 原型任务分解(2 周)

### 第 1 周
| 天 | 任务 |
|---|---|
| D1 | 环境(Vite+React18+TS+react-konva)+ 画布 Stage/Layer + 底图上传显示 |
| D2 | 图元库面板(15 图标)+ 拖拽到画布生成图元(Image/Text/Shape) |
| D3 | 选中/移动/缩放/旋转(Konva Transformer)+ 删除/复制 |
| D4 | 对齐工具 + 多选 + 成组 + 图层 z-index |
| D5 | 底图自适应 + 属性面板(绑 device_key 下拉 + 显示格式) |

### 第 2 周
| 天 | 任务 |
|---|---|
| D1 | 报警变色渲染(值区间→颜色)+ 模拟值发生器 |
| D2 | 动画(液位填充自定义 shape + 阀门旋转 rotation) |
| D3 | 保存布局 JSON(后端简单 API)+ 加载 |
| D4 | 运行时只读模式 + 实时预览 + 中英文 |
| D5 | 性能压测(200 图元)+ 调优 + 验收演示 |

## 6. 关键技术点验证方法

| 技术点 | 验证方法 | 达标 |
|---|---|---|
| 200 图元性能 | 造 200 图元页面,Chrome Performance 测拖拽/缩放帧率 | ≥30fps |
| 数据驱动渲染 | 10 图元绑 device_key,改模拟值,观察变色/文本 | 实时正确 |
| 大底图 | 上传 3MB PNG,显示+缩放 | 显示≤2s,缩放流畅 |
| 复杂交互 | 多选+成组+对齐 | 无 bug |
| 动画 | 液位填充随值变化、阀门旋转 | 流畅 |
| SVG 导入 | 1 个现有 SVG 作底图或图元 | 可显示 |

## 7. 风险点与预案

| 风险 | 概率 | 验证 | 预案 |
|---|---|---|---|
| 200+ 图元卡顿 | 中 | 性能压测 | Konva 分层缓存/像素比降/限图元数/Fabric.js |
| 大底图加载慢 | 低 | 上传测 | 压缩/分块 |
| 复杂动画实现难 | 中 | 原型做液位+阀门 | Konva 自定义 shape,需熟练 |
| 图标风格不一 | 低 | 选统一包 | 后续统一采购/绘制 |
| 移动端(未来) | — | PoC 不验 | 记录风险,后续评估 |

## 8. 验收标准(量化)

- [ ] 200 图元页面拖拽/缩放 ≥30fps
- [ ] 底图上传(3MB)显示 ≤2s
- [ ] 10 个 device_key 绑定 + 模拟值刷新正确变色
- [ ] 液位动画 + 阀门动画 各 1 个可演示
- [ ] 保存/加载布局 JSON 无损
- [ ] 运行时只读模式接模拟流,图元响应式刷新
- [ ] 中英文切换正常
- [ ] 1 个现有 SVG 成功作底图导入
- [ ] **实施人员(非开发)能用原型搭出一个简单机舱图**(关键体验验收:找 1 位实施/产品同事试用 30 分钟,观察是否需开发介入)

## 9. PoC 产出与决策点

| 结果 | 决策 |
|---|---|
| 全部达标 | R2 正式排期图元组态编辑器,按配置中心设计第 6 节落地 |
| 性能不达标 | 优化(分层/限图元数);或换 Fabric.js 重验;或限制单页图元数 |
| 复杂交互/动画不达标 | 降级:动画后置,先静态图元 + 变色 |
| 实施人员试用不通过 | 优化交互;或评估图片热区方案 |
| 多项不达标 | 评估现成组态库(HT for Web 等)或图片热区 |
