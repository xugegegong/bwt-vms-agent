# 凭据获取说明

> **本仓库不含任何密码、密钥、连接凭据。** 所有含凭据的内容已替换为占位符（如 `<MySQL密码>`）。

## 真实值向谁获取

| 用途 | 获取方式 |
|---|---|
| MySQL / Redis / 串口服务器 / 各环境登录 | **向本船交付负责人或组长（C）索取** |
| 现场实船库连接 | 现场时由交付人员当场提供（每次会话现问） |
| 办公室测试环境 | 向负责该环境的同事索取 |
| Nacos / 网关 / 第三方平台账号 | 见《用户权限域操作手册》，具体值向 C 索取 |

## 占位符约定

文档里出现的占位符含义：

| 占位符 | 含义 |
|---|---|
| `<MySQL密码>` | MySQL 连接密码 |
| `<Redis密码>` | Redis 连接密码 |
| `<设备密码>` | MOXA 串口服务器等设备的 Web 管理密码 |
| `<密码>` | 系统账号的登录密码（如 admin） |
| `<主机>` / `<端口>` / `<库名>` | 环境连接信息 |
| `sk-****` | 已打码的第三方 API Key（原文是代码里的硬编码密钥，此处只指出问题不泄露值） |

## 脚本怎么用

含连接的脚本**已移除硬编码默认值**，改为从环境变量读：

```bash
export BWT_DB_HOST=<主机>
export BWT_MYSQL_PASSWORD=<密码>
export BWT_SSH_USER=root
export BWT_SSH_PASSWORD=<设备密码>
```

缺参数时脚本会**明确报错并提示**，不会静默用错值。

| 脚本 | 需要的环境变量 |
|---|---|
| `tools/apply_to_iscu.py` | `BWT_DB_HOST`、`BWT_SSH_PASSWORD`、`BWT_MYSQL_PASSWORD`（也可用同名命令行参数） |
| `tools/snapshot_iscu.py` | 同上 |
| `tools/iscu_agent_api.py` | `BWT_MYSQL_PASSWORD`（必填，无默认） |
| `ships/*_S1产物/build_*.py` | `BWT_DB_HOST`、`BWT_MYSQL_PASSWORD` |

## 提交前自检

```bash
# 找"看起来像真实凭据"的行——注意:不在命令里写具体密码值,否则自检命令自己就成了泄露源
grep -rniE "(password|passwd|pwd|_PW)[\"']?[[:space:]]*[:=][[:space:]]*[\"']?[A-Za-z0-9@#!_.-]{6,}" . \
  --exclude-dir=.git \
  | grep -viE "<[^>]*>|占位|示例|example|placeholder|请先设置|向交付负责人"

# 私钥
grep -rl "BEGIN .* PRIVATE KEY" . --exclude-dir=.git
find . \( -name "*.pem" -o -name "*.key" -o -name "id_rsa*" \) -not -path "./.git/*"
```

**期望结果：除了本文件本身的说明文字，不应有任何输出。**

> 若想精确核对"旧密码是否清干净"，向交付负责人要一份**对照表**（不要写在仓库里）。

## ⚠️ 两条铁律

1. **不要把真实密码写回文档或脚本**——需要时用环境变量或当场输入。
   这既是安全要求，也符合本套件"连接信息不写死、每次会话现问"的原则。
2. **不要提交私钥、数据库 dump、数据目录快照**——`.gitignore` 已排除常见类型，
   但推送前请再核对一次。
